Dune Engine - Proyecto Universitario

Motor 3D desarrollado en OpenGL 3.3 y SDL3, con flujo de trabajo basado en editor e inspirado en Unity.

Empezar Más información

Descripción del Proyecto

Dune Engine es un motor de videojuegos 3D creado como proyecto académico con el objetivo de aprender el funcionamiento interno de un motor y utilizarlo posteriormente para el desarrollo de un juego.

Incluye un editor visual con gestión de escenas, GameObjects, assets y herramientas de depuración avanzadas.

Cómo usar el Motor

Ejecutar el motor

  • Se crea una ventana OpenGL (800×600) con depth test activado.
  • Inicialización de SDL3, DevIL y Assimp.
  • Información de GPU y OpenGL en consola.
  • Carga automática de StreetEnvironment.fbx.

Carga de modelos y texturas

  • Drag & Drop de modelos y texturas.
  • Los modelos se instancian frente a la cámara.
  • Las texturas se aplican al objeto seleccionado o bajo el cursor.

Controles

Cámara

W/A/S/D (RMB), SHIFT velocidad, ALT + RMB órbita, rueda zoom, F enfocar, ESC salir.

Gizmos

W: mover · E: rotar · R: escalar

Visualización

Wireframe activable desde Scene Panel

Funcionalidades Principales

  • Editor visual con jerarquía e inspector.
  • Selección por raycast y colisiones AABB.
  • Cámara FPS, órbita y zoom.
  • Sistema de shaders.
  • UI completa con ImGui.
  • Logs y debug de GPU y OpenGL.

Soporte de Plataformas

  • Windows
  • macOS
  • Linux

Soporte multiplataforma mediante CMake.

Editor e Interacción con la Escena

  • Reparentado por drag & drop.
  • Creación y eliminación de GameObjects.
  • Duplicado y renombrado.
  • Primitivas: Cube, Sphere, Plane, Cylinder, Cone, Torus, Capsule.

Gestión de Assets

  • Explorador de proyectos con búsqueda.
  • Archivos .meta para importación.
  • Library regenerada automáticamente.
  • Reference counting para evitar duplicados.

Play, Pause y Stop

  • Play: inicia simulación.
  • Pause: pausa el estado.
  • Stop: restaura el estado inicial.
  • Control de velocidad y ejecución paso a paso.

Render y Debug

  • AABB visibles en modo editor.
  • Raycast debug activo.
  • Frustum Culling visualizado.
  • Octree como estructura de aceleración.

Requisitos del Encargo Implementados

  • Inspector completo.
  • Gestión de jerarquía.
  • Serialización de escenas.
  • Sistema de Library propio.
  • Play / Pause / Stop.
